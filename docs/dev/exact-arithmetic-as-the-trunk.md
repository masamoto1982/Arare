# 厳密算術を幹とする位置づけ（2026-10-20）

Status: non-canonical. 方針記録。正典は `spec/language-semantics.md` の
LANG.VALUES.EXACT・LANG.VALUES.TRUTH・LANG.CONTRACT.FIELD。本書は判断の理由と、
外部の議論から採らなかった提案とその理由だけを記録し、何も定義しない。

## 判断

Ajisai を他と分けるのは、厳密算術と分数の輪（全域除算）の組である。厳密算術だけなら
既存の数式処理系にあり、全域除算だけなら浮動小数点の NaN と Inf にある。組にした
ときにだけ、丸めのない数が除算でも止まらずにベクトルを流れ、しかも輪の公理が全点で
成り立つ。三値論理はこの組の脇にあり、算術との橋は「0 の上の点に順序を問うと
`domainMiss` になり、真偽の位置で UNKNOWN と読まれる」の一本だけである
（`wheel-of-fractions.md`、`three-valued-truth.md`）。

この組から読み取れて、浮動小数点では成り立たない性質のうち、利用者に最も効くのは
**和と積が順序に依らない**ことである。加法と乗法は輪の全点で可換モノイドなので、
`FOLD` の被演算子を並べ替えても組み直しても答えは変わらない。0 の上の点に出会った
後でも同じである。README の厳密算術の項にこれを書き、`rust/src/zero_shape_laws.rs`
の法則 6 が、標本から選んだ四つの被演算子のすべての並びについて、連鎖と `FOLD` の
両方で確かめる。同じ法則表には輪の公理として交換律を加えた（それまでは整数の
proptest にしかなかった）。

## 外部の議論から採らなかったもの

2026-10 に、作者と他の AI との対話で開発方針が議論された。その AI はリポジトリの
コードを読めていなかった。結論の方向（厳密算術と輪が主役で、三値論理は脇役）は
上の判断と一致するが、途中の提案には現行の設計と食い違うものがあった。同じ提案が
また出たときのために、採らなかった理由を書いておく。

| 提案 | 採らない理由 |
| --- | --- |
| 有限の数 < ∞ を TRUE とする順序の拡張 | 符号つきの無限大は逆数の対合を壊すので、2026-10-12 に退けた（`wheel-of-fractions.md`）。`1/0` は符号も順序も持たない。順序を問えば `domainMiss` で、真偽の位置では UNKNOWN |
| 輪の加法は結合的でないので、`FOLD` の組み直しを `field=closed` の下でだけ許す | 前提が誤り。加法と乗法の結合律と交換律は全点で成り立つ（法則 4・6）。崩れるのは 0 に言及する体の法則（`0·x = 0`、`x − x = 0`、`x ÷ x = 1`）と分配律で、`field=closed` が範囲を示すのはそちらである（LANG.CONTRACT.FIELD） |
| 契約の判定と真理値で、一つの三値型を共有する | 零形は抽象領域であって真理値ではない（`three-valued-truth.md`）。`field` は `closed` < `leaving` の二値で、推論が読めないものは「検証できない」（gap）になる。検査の三つの結果が対応するのは値・NIL・エラーの三分法であり、真理値の三つではない（`trichotomy-unification.md`） |
| ベクトルの一要素が NIL なら、ベクトル全体を NIL にする | 要素ごとの伝播が LANG.COLLECTIONS.LIFT の約束である。`[ 4 -1 9 ] SQRT` は `[ 2/1 NIL 3/1 ]` で、影響を受けるのはその要素だけ。答えが全要素の順序に依存する `SORT` などだけが全体を `domainMiss` にする |
| 契約を性能の予測に使う | `field=closed` は分母の大きさを縛らない。体の中でも分母は伸びる。費用は作業メーター（LANG.MACHINE.LIMITS）が数えて上限で止めるので、予測の役は契約ではなくメーターにある |
| 代数的無理数を最小多項式の次数で打ち切る | すでに有界である。値の域は平方根で生成される多二次体の正規形で、被開平数の因数分解は数値作業に課金され、残りの作業で分解できなければ `resourceLimitExceeded`（LANG.VALUES.EXACT） |
| 決定性を最大の売りにする | 実行は初期状態に対して決定的（LANG.MACHINE.TRANSFORMERS）で、`scripts/bench/wasm-parity.mjs` が二つの WASM ビルドの答えを照合している。ただし IEEE 754 の四則も決定的なので、差別化としては弱い。差別化として正確なのは上の順序非依存性である |

数式処理系（FLINT、SymPy など）との速度比較は `exact-arithmetic-benchmark-2026-10-21.md`
に測定した。速度を何と約束するかは、引き続き `rust-10k-reduction-plan.md` が作者の
判断事項に挙げている。
