## 0. 要約

- 4 回の較正で、Opus・Sonnet・Haiku・Fable の各 1 体、計 16 体が 252 問を解いた（4 回とも cli 経路、
  辞書なしの solo、世代 0 のみ）。**誤答が出たのは、コードを一度も走らせない条件だけ**だった。
  その条件での Fable の 3 問（57/60）である。
- コードを 1 回でも走らせられる限り、課題の難しさは誤答としては現れなかった。現れたのは実行回数の差で、
  上限なしでは同じ課題に Opus が 116 回、Haiku が 1,184 回走らせた。
- 実行回数に上限（10 回）を設けても、全員がテストを 1 回の実行にまとめて 2〜4 回で全問正答した。
  上限が効くのは 0 回のときだけである。
- 無実行条件の誤答の原因は一つだった。`SELECT` が「値」ではなく「レーン」を選ぶことである。
  長さの違う 2 つの Vector を一つの真理値で選ぼうとして `shapeMismatch` になった。上限なしの回では、
  同じ Fable がこの挙動を実行で見つけて避けていた。
- したがって、Phase 3 で正答率を指標にするなら、無実行の条件を置く。そこで測るのは
  「SKILL.md だけから初手で正しく書けるか」であり、AI のための言語として Ajisai が答えるべき問いでもある。

## 1. 4 回の条件と結果

| 回 | 課題族 | 実行の上限 | 正答 | 体ごとの実行回数（Opus / Sonnet / Haiku / Fable） |
| --- | --- | --- | --- | --- |
| 1 | sensor・orders・messy（Ajisai 固有の罠） | なし | 72/72 | 65 / 102 / 92 / 21 |
| 2 | runs・number・brackets（アルゴリズム） | なし | 60/60 | 116 / 150 / 1,184 / 153 |
| 3 | 2 と同じ | 10 回 | 60/60 | 3 / 2 / 4 / 2 |
| 4 | 2 と同じ | 0 回 | 57/60 | 0 / 0 / 0 / 0 |

- 回 1 の罠: NIL の素通し（`ADD` は NIL を答える）、前方補完の `SCAN`、ゼロの読みでの除算（`1/0`・`0/0`
  になり ERROR にならない）、JSON の欠けたキー（`NIL(notFound)`）、`FORMAT` の丸め（同点は 0 から遠い方、
  `10.205` → `'10.21'`）、`TOKENIZE` が連続空白から作る空文字列。見せる入力にはどの罠も出さず、
  見せない入力にだけ出した。入力の種類の説明では、罠の存在に触れた。
- 回 2 の課題: 素数、2 進表記、Collatz の段数、Fibonacci の添字（無制限ループのない言語では、
  反復回数を先に上から押さえる必要がある）、ラン長符号化、多数派（なければ NIL）、2 種類の括弧の
  釣り合い、最長の釣り合う接頭辞など。
- 全回とも、参照解はエンジンで全入力について確かめ、手計算とも突き合わせた。

## 2. 観察

### 2.1 説明に出した罠は罠にならない

回 1 で、全員が見せない入力の罠まで正答した。入力の種類の説明に「NIL を含みうる」「0 や負を含みうる」
「キーは欠けうる」と書けば、各被験体は自分でその入力を作って試した。罠を説明から隠せば誤答は出せるが、
それは言語の習得ではなく問題文の不備を測ることになる。

### 2.2 実行できる限り、難しさは「回数」に出る

回 2 で、Haiku は 1,184 回走らせて 15/15 に達した。誤った実行は 88 回だった。同じ課題で、Opus は 116 回
（誤った実行 1 回）だった。上限のない実行ループの中では、被験体は通るまで直し続ける。モデルの差は
正答率ではなく、到達にかかった試行の数に現れた。

### 2.3 上限は 0 でないと効かない

回 3 では上限 10 回に対し、全員が 2〜4 回で済ませた。Haiku は回 2 の 1,184 回から 4 回になり、
それでも 15/15 だった。1 回の実行に多数の式を並べて一度に確かめる書き方に、全員が切り替えた。
「1 回の実行に多くのテストを入れてよい」と明記したことも効いている。

### 2.4 無実行で残った誤り — `SELECT` は値でなくレーンを選ぶ

回 4 の誤答は、Fable の brackets 3 問（balanced・balanced_prefix・unmatched）だけで、原因は一つである。
括弧の照合を Vector のスタックで書き、「取り出した後のスタック」と「積んだ後のスタック」を一つの真理値で
`SELECT` した。`SELECT` は要素ごとに選ぶので、長さの違う 2 つの Vector の間では
`shapeMismatch`（`expected shapes that align, got [0] and [2]`）になる。

- SKILL.md §3 は「選択はレーンごと」と書いている。しかし「2 つの Vector を丸ごと選ぶには `SELECT` を
  使えない」とは書いていない。
- 無実行の Opus は、この危険を自分で予想していた。2 つの値を Vector に入れて `GET` で一つを取り出す
  自前の語（`S0A.IF`）を作って避けた。
- 回 2・回 3 の Fable は、実行してこの挙動を見つけ、スタックを String で持つ書き方に変えていた。

AI が初手で書くとき、言語のどこでつまずくかを、この条件は具体的に示した。SKILL.md に「値を丸ごと選ぶ
には `2 COLLECT` して `GET` で選ぶ」と一行足せば、この誤りは防げる見込みが高い。ただし、足すかどうかは
本書では決めない。足すと、以後の実験の基準線（被験体が読む文書）が変わる。

### 2.5 同じ課題に対する書き方の分岐

| 課題 | 書き方 |
| --- | --- |
| Collatz の段数 | 全員が反復回数を固定した（130〜250 回。参照解は 120 回）。「1 に達したら 1 のまま」とする者と、[値 段数] の対を運ぶ者がいた |
| 括弧の釣り合い | `REPLACE` で `()`・`[]` を消す操作を上限回数繰り返す（参照解と Opus 回 2・Fable 回 3）か、スタックを `FOLD` で運ぶ（Opus 回 3・回 4、Fable 回 2・回 4）か |
| 桁根 | 回 2〜4 の 12 解答のうち 11 が公式 `1 + (n-1) mod 9`（同値な 2 形）を使い、1 解答（Haiku、回 3）が桁和を 3 回取った |
| 2 つの値の丸ごとの選択 | `SELECT` を避ける自前の語（Opus）、String に持ち替える（Fable）、`SELECT` で失敗（無実行の Fable） |

## 3. 限界

- 各回、各モデル 1 体。差は兆候であって、統計的な主張ではない。
- 被験体が読むファイルの制限は指示であり、検査していない。無実行の回（4）の間は、前の 3 回の解答を含む
  実行記録を作業木の外へ退避した（コミット済みなので、git から読むことは可能だった）。どの被験体も
  道具の呼び出しは 4〜6 回で、ファイルの探索をした形跡はない。
- 回 1〜3 の被験体の一部は、作業ファイルをセッションの共有領域（scratchpad）に置いた。回 3 の前に、
  解答を含むものを共有領域から退避した。
- 無実行条件の「0 回」は、cli 経路の `compute` が拒むことで保証している。被験体が別の手段
  （`ajisai` バイナリ、MCP ツール）で走らせることは禁止したが、技術的には防いでいない。

## 4. Phase 3 に向けて（観察から。決定ではない）

1. 正答率を指標にするなら、無実行（`"callBudget": 0`）の条件を置く。実行ありの条件では、正答率ではなく
   到達までの実行回数を指標にする（`calls/<agent>.jsonl` の行数）。
2. 無実行で誤りを生む箇所（今回は `SELECT` のレーン選択）は、言語の学びやすさの所見として扱う。
   SKILL.md を変えるかは、実験の基準線との兼ね合いで決める。
3. 課題族は、回 2 の 3 族（runs・number・brackets）が無実行で差を出した。回 1 の 3 族は、無実行でも
   差が出るかを未確認である。
