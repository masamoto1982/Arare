## 0. 要約

- 18 体 × 18 問 = 324 解答がすべて正答した。採点はすべてエンジンで行い、被験体には見せない入力も使った。
  被験体は Opus・Sonnet・Haiku で、3 モデルとも全問正答した。
- **系統混在の基準線を初めて測れた。** 辞書を継承しない 6 体（3 モデル × 2 体）の間で、定義した
  同値類の重なり（Jaccard の平均）は同一モデルの対で 0.37、異なるモデルの対で 0.24 だった。
  収束の一部はモデルの事前分布で説明できる。それでも、2 体以上が独立に到達した 19 類のうち
  16 類は、2 つ以上のモデルから到達された。
- **辞書は 1 世代で固定点に達した。** bottleneck の gen1 と gen2 の辞書は同じ 8 語で、並び順だけが違う。
  8 語のうち 7 語は gen0 の Opus 被験体 1 体が定義した語である。
- **最も多く再発明された語は、一度も辞書に入らなかった。** 先頭文字の大文字化（14 体）と
  絶対値（13 体）である。選定は「正答解答からの使用回数」で順位を付けるので、多くの課題から
  使われる語が勝つ。1 課題でしか使われない語は、何体が作っても勝てない。
- **C-shuffled: 継承語の再利用は名前にも注記にも依存しなかった。** 名前を無意味な綴りに替え、
  注記を消しても、再利用はほぼ同じだった（正答解答のうち継承語に届いた割合: bottleneck 46/54・45/54、
  shuffled 44/54・45/54）。被験体は本体を読んで使っている。
- **H5: 不一致 0 件（324 中）。** cli 経路の記録では、継承語を名指した 602 回の実行すべてで、
  `prelude` のダイジェストが辞書と一致した。パイロットで反例を生んだ「定義の貼り付け」は、
  この経路では起きない。
- **前提のうち満たせなかったもの**: 系統の異なるモデル（Claude 以外）の混在。課題は難しくしたが、
  正答率には分散が出なかった（§5）。

## 3. 仮説ごとの観察

### 3.1 H1（独立到達）— 系統をまたぐ収束はあるが、同一モデルの方が強い

辞書を継承しない 6 体（bottleneck gen0 と solo）の各対について、定義した同値類の Jaccard を取った。

| 対の種類 | 対の数 | Jaccard の平均 |
| --- | --- | --- |
| 同一モデル | 3 | 0.37 |
| 異なるモデル | 12 | 0.24 |

- 同じモデルの 2 体は、類の重なりが約 1.5 倍大きい。Opus の 2 体（G0A・S0A）は `RUNMAX`・
  `TRIMMED`・`WORDS`・`SUM` を字面まで同じに書いた（D0 一致）。パイロットの停止条件 (1)
  （同一モデルの複数体がほぼ同一の定義を初手から出す）は、同一モデルの対では今回も成り立つ。
- 全条件・全世代を通して、2 体以上が独立に到達した類は 34 類中 19 類で、うち 16 類は 2 つ以上の
  モデルから到達された。3 モデルすべてから到達された主な類は次のとおり。

| 類 | 到達体数 | 書き方 |
| --- | --- | --- |
| 先頭文字の大文字化（CAP） | 14 | `CHARS … 0 GET UPPER … 1 DROP JOIN 2 COLLECT JOIN` 系・`… 1 COLLECT … CONCAT JOIN` 系・`PUT` 系の 3 通り |
| 絶対値（ABS） | 13 | `X 0 X SUB MAX`・`X X -1 MUL MAX`・`2 POW SQRT` |
| 空白での結合（JOINSP） | 7 | `[ ' ' 2 COLLECT ] MAP FLATTEN JOIN TRIM` 系と FOLD 系 |
| 中央値（MEDIAN） | 6 | 6 体全員。添字 2 つを `FLOOR` で求める形に全員が到達した |

- Core に絶対値の語はない。`ABS` は退役済みで、`spec/retired-words.json` は代わりの句として
  `'X' BIND X X MUL SQRT` を挙げる。13 体がそれを作り直し、書き方は 3 通りに分かれた。退役語の句に
  近い形（`2 POW SQRT`）は 1 体だけで、ほかは `MAX` を使う形だった。

### 3.2 bottleneck の辞書 — 1 世代で固定点、最多の再発明は入らない

gen1 の辞書（K = 8、使用回数順に選定）:

| 語 | 本体 | 選定時の使用数 |
| --- | --- | --- |
| `G0A.SUM` | `0 [ ADD ] FOLD` | 14 |
| `G0A.MEAN` | `'V' BIND V G0A.SUM V LENGTH DIV` | 6 |
| `G0A.MEDIAN` | `SORT 'V' BIND V LENGTH 'N' BIND V N 1 SUB 2 DIV FLOOR N 2 DIV FLOOR 2 COLLECT GET G0A.MEAN` | 6 |
| `G0A.WORDS` | `' ' TOKENIZE` | 6 |
| `G0A.ARGMAX` | `'L' BIND 0 L SUB ORDER 0 GET` | 5 |
| `G0A.UNWORDS` | `'V' BIND V 1 DROP V 0 GET [ 'E' BIND ' ' E 3 COLLECT JOIN ] FOLD` | 3 |
| `G0A.BYNAME` | `ZIP [ 'N' 'A' ] BIND N A GROUP 'G' BIND G KEYS G VALUES [ G0A.SUM ] MAP RECORD` | 3 |
| `G0B.TOPKEY` | `'T' BIND T KEYS T VALUES -1 MUL ORDER 0 GET GET` | 3 |

- gen2 の辞書は同じ 8 語だった。gen1 の 3 体全員が 8 語すべてを使ったので、継承語の使用数が
  gen1 で新しく作られた語（各 1 体）を上回り続ける。継承された語は、使われることで次も選ばれる。
- 8 語のうち 7 語は G0A（Opus）1 体の語である。Opus は語を多く作り（§2）、自分の解答から自分の語を
  呼ぶので使用数が積み上がる。辞書は「最も多く定義した被験体の語彙」になった。
- 一方、最も多く再発明された CAP（14 体）と ABS（13 体）は、どの世代の辞書にも入らなかった。
  どちらも 1 体の中では 1〜2 問からしか使われないので、使用回数の順位で負ける。辞書に入らなかった
  語は、パイロットと同じく、次の世代の各体が作り直した（gen1・gen2・shuffled の 12 体のうち、
  CAP は 9 体、ABS も 9 体）。

### 3.3 C-shuffled — 再利用は本体を読んで起きている

| 条件 | 世代 | 正答解答のうち継承語に届いた割合 | 体ごとの、届いた継承語の数 |
| --- | --- | --- | --- |
| bottleneck | 1 | 46/54 | 8・8・8 |
| bottleneck | 2 | 45/54 | 8・8・8 |
| shuffled | 1 | 44/54 | 8・7・8 |
| shuffled | 2 | 45/54 | 8・8・8 |

名前（`X1.RUKUTA` など）にも注記にも意味がない辞書で、再利用は bottleneck とほぼ同じだった。
shuffled gen1 から evolve した辞書も、改名前の 8 語と同じ類だった。少なくともこの規模の本体
（最長でも 30 トークン以下）なら、被験体は本体を読んで何をする語かを理解している。パイロット §5.3 の
問い（再利用は名前と注記に依存するか）への答えは、「この条件では依存しない」である。

### 3.4 H2（構成性）— 辞書が固定されたので変化しない

他の辞書語を本体で呼ぶ語は、どの辞書でも 3/8（`MEAN`→`SUM`、`MEDIAN`→`MEAN`、`BYNAME`→`SUM`）。
辞書が gen1 で固定されたので、世代による変化は測れなかった。被験体自身の語には、継承語の上に組んだ
ものが多い（例: `G1B.DEBTORS` = `G0A.BYNAME 'R' BIND R KEYS R VALUES 2 COLLECT ZIP [ 1 GET 0 LT ] FILTER [ 0 GET ] MAP`）。
しかし、それらは辞書に入らないので、構成性は次の世代へ渡らなかった。

### 3.5 H4（Core の使用頻度）

正答解答から（ユーザー語を展開したうえで）到達された Core 語は 39、未使用は 38 だった。
上位は `GET` 264・`BIND` 263・`FOLD` 164・`ADD` 145・`MAP` 141。課題が数値・テキスト・帳簿に偏るので、
NIL 系・Record の部分更新・JSON・`SELECT` は使われていない。`MIN` は 0 で、最小値は `SORT` と `ORDER` で
取られた。パイロットと同じく、この数字は課題族の選び方で決まるので、退役の根拠には使えない。

### 3.6 H5（監査可能性）— 反例なし

- 正答 324 件すべてで、ユーザー語を本体へ展開した Core のみのプログラムが同じ結果を出した。
- cli 経路の記録: 被験体の実行は全 1,012 回、うち継承語を名指したのは 602 回。602 回すべてで、
  結果の `prelude` が名指した語のダイジェストは `lexicon-digests.json` と一致した。被験体が走らせた
  プログラムは、辞書が内容で定める語を使っている。

## 6. 限界

- 被験体はすべて Claude である。「系統をまたぐ収束」（§3.1）は Claude の 3 モデル間の収束で、
  学習の系譜を共有するモデルどうしである。
- 各条件 3 体、bottleneck 3 世代・shuffled 2 世代の小標本で、統計的な主張はしていない。
  基準線の同一モデル対は 3 対しかない。
- 課題族と参照解を作ったのは本書の作者で、被験体と同じ系統のモデルである。
- 「指定のファイル以外を読むな」は指示であり、検査していない（M-7）。

## 7. Phase 3 に進む前に必要なこと（観察から。提案であって決定ではない）

1. **他社モデルの被験体。** route B のハーネスを別の API に対応させ、その鍵を環境に置く。
   同一モデル対と異なるモデル対の差（0.37 対 0.24）が、系統をまたいでどこまで縮むかを測る。
2. **正答率に分散を出す課題。** 見せない入力の境界の場合だけでは足りなかった。入力の種類そのものを
   説明文でしか示さない課題や、手順が長く途中の値を名付けないと書けない課題を考える。
3. **選定規則の比較（M-6）。** 使用回数だけで選ぶと、辞書は最初に多く定義した被験体の語彙で固定される。
   独立到達の数を加味する規則を、C-bottleneck の変種として比べる。
4. **C-open（K 無制限）。** 辞書が固定点に達するのが容量のせいかを切り分ける。
