## 0. 要約

- 52 体（Opus・Sonnet・Haiku・Fable 各 13 体）が、コードを走らせずに 1 体 39〜44 問を解いた。
  学習の課題族は 2 組（A・B）を世代ごとに入れ替え、`messy`・`series`・`ledger` の 3 族は
  **選定に使わない held-out** として毎世代解かせた。
- **P1（汎化）: 継承した辞書は、選ばれなかった課題でも呼ばれた。** 世代 1〜3 の held-out の正答の
  42〜75%（`breadth` を除けば 61〜75%）が継承語を 1 つ以上呼んだ。ただし呼ばれたのはごく一般的な数語（単語分割・合計・平均・
  キーごとの合計・最大の位置）で、族による差が大きい。`messy` はほぼ全問、`ledger` は 3 分の 2、
  `series` は 1〜4 割だった。
- **ただし、辞書は解答を短くしなかった。** held-out の解答の長さを Core のみへの展開で割った値は、
  辞書なしの世代 0 が 0.199、辞書ありが 0.197〜0.299 で、縮んでいない。辞書の語は、被験体が自分で
  書くはずだった補助語を置き換えただけである。使用量（1 体あたりのトークン）も減らなかった。
- **P2（入れ替え）: 入れ替えても、容量なしの辞書は課題を丸ごと解く語で埋まった**（各世代で
  37〜44 語のうち 18〜19 語が 1 課題にしか届かない語）。ただし、その語は次の世代の学習課題に
  効かないので、使われなかった。学習課題の正答のうち継承語を呼んだのは 41/83・69/104・49/84 で、
  Phase 3 の C-open（128/132）とは違う。解答の短縮率も 0.26〜0.28 で、Phase 3 の 0.052 には
  ならなかった。入れ替えは、解答集を作らせないのではなく、解答集が役に立たないようにした。
- 入れ替えない `fixed` の辞書は、3 世代とも同じ 8 語のまま固まった。入れ替える `uses` は、
  一般的な 3 語（単語分割・合計・平均）だけを残し、残りを毎世代入れ替えた。前の学習組の語は
  一度落ち、次の世代に**名前を変えて作り直されて**戻った。held-out の再利用は `uses` と `fixed` で
  変わらなかった。
- **P3（選定規則）: `breadth`（届いた課題の数で並べる）は `uses` に勝たなかった。** held-out の
  再利用は 49 → 35 → 30 と 3 世代で最も低くなった。課題の数を数える規則では、1 つの族の中だけで
  4 課題に届く語（括弧の符号化など）が一般的な語より上に来た。同じ働きの語が 2 つ（平均）枠を
  取った。
- **P4（忘却）:** キーごとの集計の語は、学習 B の世代で `uses` の辞書から落ちた。それでも
  held-out の `ledger` の再利用は 17 → 20 → 16 と下がらなかった。合計と最大の位置の語が代わりを
  務めたからである。代わりの語も持たなかった `breadth` では、17 → 8 → 9 に下がった。
- 正答は 2,157/2,168（99.5%）。誤り 11 件はすべて被験体自身の式で、`SELECT` の `shapeMismatch` は
  0 件だった。

## 2. 汎化（P1）

### 2.1 held-out の正答のうち継承語を呼んだもの

| 条件 | 世代 1 | 世代 2 | 世代 3 |

族ごと（左から世代 1・2・3、分母は各族の正答数）:

| 条件 | `messy` | `ledger` | `series` |
| --- | --- | --- | --- |
| uses | 24・24・24 | 17・20・16 | 4・10・4 |
| breadth | 23・24・18 | 17・8・9 | 9・3・3 |

| fixed | 24・24・23 | 16・16・15 | 4・6・6 |

（分母は各族の held-out の正答数で、24 か 23）

held-out で呼ばれた継承語は、どの条件でも次の数語に集中した: 単語分割（`G0A.WORDS`）、合計
（`G0A.SUM` とその作り直し）、平均、キーごとの合計（`G0A.SUMBY`・`U2A.GSUM`・`O2A.BYKEY`）、
最大の位置（`*.ARGMAX`）、最大の値のキー（`G0A.TOPKEY`）、空白での連結（`*.UNWORDS`・
`G0B.SPACED`）。`messy` の全問は単語分割を、`ledger` は合計とキーごとの合計を通る。`series`
（中央値・移動平均・最頻値）に効く一般語は辞書にほとんど入らなかった。

### 2.2 短縮と労力

| 条件 | 世代 | held-out の tokens ÷ expanded | 1 体が自分で定義した語 | その本体のトークン数 | 1 体の使用量 |
| --- | --- | --- | --- | --- | --- |
| base | 0 | 0.199 | 24.3 | 312 | 12.8 万 |
| uses | 1・2・3 | 0.205・0.268・0.268 | 17.0・11.8・12.3 | 267・185・193 | 13.5・12.5・14.1 万 |
| breadth | 1・2・3 | 0.209・0.299・0.253 | 16.0・15.5・22.5 | 314・236・340 | 13.9・12.5・13.8 万 |
| open | 1・2・3 | 0.197・0.260・0.206 | 14.5・12.3・13.5 | 238・185・241 | 13.2・12.6・13.8 万 |
| fixed | 1・2・3 | 0.229・0.198・0.246 | 14.8・19.5・13.0 | 223・291・179 | 12.4・12.5・12.4 万 |

継承語は解答を短くしなかった。被験体は辞書がなくても自分で補助語を定義して短く書き、辞書が
あるとその一部を継承語に置き換える。自前の定義は世代 0 の 24 語から 12〜22 語に減ったが、条件・
世代でばらつき、使用量は減っていない。**辞書の効果は「同じ語を書かずに済む」ことで、それは
解答の長さにも労力にも目立って現れない。**

## 3. 辞書の動き

### 3.1 入れ替えの有無（P2）

| 条件 | 世代 1 | 世代 2 | 世代 3 |
| --- | --- | --- | --- |
| fixed | `G0A.SUM` `G0A.WORDS` `G0C.ORDERS` `G0A.MEAN` `G0A.MOD` `G0A.SUMBY` `G0A.DEVS` `G0A.VAR` | 同じ 8 語 | 同じ 8 語 |
| uses | 同上 | `G0A.WORDS` `U1B.RED1` `U1A.UNWORDS` `U1A.ARGMAX` `G0A.SUM` `U1C.STARTIDX` `U1B.CAP1` `G0A.MEAN` | `G0A.SUM` `G0A.WORDS` `G0A.MEAN` `U2A.ORDERS` `U2A.GSUM` `U2D.DEVS` `U2D.VAR` `U2A.DIVS` |

`fixed` は Phase 3 の `uses` と同じく、1 世代目で固まって動かなかった。入れ替える `uses` は、世代 2
で学習 B に効く語（括弧の 1 段消去・空白での連結・最大の位置・語頭の大文字化）に入れ替わり、世代 3
で学習 A の語に戻った。戻った `U2A.ORDERS`・`U2A.GSUM`・`U2D.DEVS`・`U2D.VAR` は、世代 1 の
`G0C.ORDERS`・`G0A.SUMBY`・`G0A.DEVS`・`G0A.VAR` と同じ本体（または同じ類）で、世代 2 の被験体が
辞書になかったために作り直したものである。3 世代とも残ったのは、どちらの組にも効く単語分割・
合計・平均の 3 語だけだった。

### 3.2 容量なし（open）

| 世代 | 語数 | うち 1 課題にしか届かない語 | 他の語から組み立てた語（H2） |
| --- | --- | --- | --- |
| 1 | 39 | 19 | 18 |
| 2 | 44 | 19 | 17 |
| 3 | 37 | 18 | 18 |

入れ替えても、容量なしの辞書は直前の世代の学習課題を丸ごと解く語（素数・二進・Collatz・
括弧の最長平衡接頭辞・比率など）で半分が埋まった。ただし、それは次の世代が解かない課題の
答えである。学習課題の正答のうち継承語を呼んだのは 41/83・69/104・49/84 で、学習課題の短縮率も
0.28・0.264・0.267 にとどまった（Phase 3 の C-open は世代 3 で 128/132、0.052）。held-out では
`open` が 52〜54/72 と最も安定して高かった。大きな辞書には、一般語が漏れなく入っているからである。

### 3.3 `breadth`（P3）

| 世代 | 辞書 |
| --- | --- |
| 1 | `G0A.SUM` `G0A.WORDS` `G0C.ORDERS` `G0A.MOD` `G0A.MEAN` `G0C.MAXV` `G0A.DEVS` `G0B.COUNT` |
| 2 | `G0A.WORDS` `W1C.CODE` `W1A.UNWORDS` `W1A.ARGMAX` `W1B.R1` `W1D.PRESENT` `G0A.MOD` `W1C.STEP3` |
| 3 | `W2B.SUM` `G0A.WORDS` `W2A.ORDERS` `G0A.MOD` `W2A.MEAN` `W2B.MEAN` `W2B.DEV` `W2B.VAR` |

`breadth` は「届いた課題の数」で並べる。世代 2 の辞書には、`brackets` 族の 4 課題すべてに届く
括弧の符号化（`W1C.CODE`）と、括弧の状態を 5 進数に詰める特殊な語（`W1C.STEP3`）が入った。
1 つの族の中で多くの課題に届く語は、族をまたぐ一般語と同じ点数になる。世代 3 には同じ働きの
平均が 2 つ（`W2A.MEAN`・`W2B.MEAN`）入り、1 枠を無駄にした。同じ類に、プローブ（D1）でだけ一致した
別の平均の書き方が混じっていたので、道具はこの類を代表 1 語に書き換えず、`W2B.DEV` が依存する
`W2B.MEAN` をそのまま運んだ（D1 の一致は同じ語の証明ではない、という設計どおりの動き）。課題の数ではなく**族の数**で並べる規則なら、両方を避けられた。

### 3.4 忘却（P4）

キーごとの合計（`G0A.SUMBY`）は、学習 B を解いた世代 1 の `uses` で使われず、世代 2 の辞書から
落ちた。世代 2 の held-out `ledger` の再利用は 20/24 で、下がらなかった。合計（`G0A.SUM`）と最大の
位置（`U1A.ARGMAX`）が `ledger` の大半を支えたからである。`breadth` は世代 1 から `SUMBY` を
持たず、世代 2 は `ARGMAX` はあっても合計がなく、世代 3 は合計はあっても `ARGMAX` がなかったので、
`ledger` の再利用は 17 → 8 → 9 に下がった。忘却が見えるのは、代わりになる一般語も辞書に
なかったときだけだった。

## 6. 汚染の統制

- 52 体すべてで、被験体が受け取った最初のメッセージが `cli.mjs prompt … --route cli` の出力と
  一字一句一致することを、記録から機械的に確かめた。
- 各世代の採点と選定の直後に `seal` した。条件どうしは独立なので、先に揃った条件から次の世代へ
  進めた（例: `uses` の世代 2 は `fixed` の世代 1 が終わる前に始めた）。辞書の出所はどれも同じ条件の
  前の世代だけである。
- 参照解と字句まで同じ正答は 30 体で計 62 件。すべて短い定型の式（`series.runmax` の
  `[ MAX ] SCAN`、`ledger.count_names`、`series.moving3`、`stats.range`、`text.*` の 1 行の式など）
  だった。
- U3C（Haiku）は、自身の報告によれば、セッションを片付ける道具を仮の ID で 1 回呼び、拒まれた。
  何も変わっていない。課題と無関係な道具の呼び出しは、これ以外に報告されていない。
- Phase 3 の補助ファイル（被験体の作業の残りを含む）は、実施前にリポジトリと共有領域の外の
  隠しディレクトリへ移した。過去の生データは git 履歴にある。被験体が git を読むことは禁止
  したが、技術的には防いでいない。

## 7. 使用量

52 体で計 680 万トークン（1 体 10.4 万〜21.4 万）。モデル別の 1 体平均は Haiku 17.9 万、Sonnet
12.1 万、Fable 11.5 万、Opus 10.9 万。所要時間は 1 体 2.7〜8.9 分。設計の見込み（650 万〜1,400 万）の
下限付近だった。

## 8. 次に進むなら（観察から。決定ではない）

1. 継承の効果が「短縮」にも「労力」にも出ないのは、被験体が辞書なしでも補助語を自分で書くから
   である。辞書の価値を測るには、自前の定義を禁じる（または数を絞る）条件を対照に置き、
   継承語だけでどこまで書けるかを見るのが筋である。
2. 一般語は族の数で選ぶのがよい。`breadth` を「届いた族の数」で並べる。プローブでだけ一致した語を
   含む類が辞書の枠を重ねて取る点は、選定の側で数え方を決めておく必要がある。
3. `series` のように一般語の届かない族がある。held-out を族単位でなく系統単位で選び、学習組に
   同じ系統の族を必ず入れれば、汎化の失敗と系統の欠落を分けられる。
4. 正答率は 99.5% で、P1〜P4 のどれにも分散を与えなかった。言語の学びやすさを測る指標として
   正答率はこの課題集合では尽きている。
5. どれに進むかは所有者が決める。

## 付録 A. 再現の要点

- 道具: `lib/rotation.mjs`（`design.json` の `rotation`）、`grade` の `heldOut`、`evolve --rule breadth`、

- held-out の再利用は `report.md` の表、族ごとの内訳は `graded/` を族で数えた（生データから再計算できる）。
- 辞書の語ごとの「届いた課題の数」は `lexicon.json` の `tasks`。

## 付録 B. 設計の要点（削除した設計書から）

### B.1 問い

| 番号 | 問い |
| --- | --- |
| P1（汎化） | 継承した辞書は、選定に使わなかった課題でも再利用され、解答を短くするか |
| P2（入れ替え） | 学習課題を世代ごとに入れ替えると、辞書は課題を丸ごと解く語で埋まらなくなるか |
| P3（選定規則） | `breadth` は、`uses` の早い固定と `reinvention` の振動を避けつつ、held-out の再利用を上げるか |

| 補 | 正答率（記録だけ。天井は止める理由にしない） |

| 条件 | 世代 | 被験体 | 辞書 | 学習課題 |
| --- | --- | --- | --- | --- |
| `base` | 0 | G0A〜G0D | なし（世代 1 の 4 条件の辞書の出所） | A |
| `uses` | 1〜3 | U*g*A〜D | 使用回数順、K = 8 | B・A・B |
| `breadth` | 1〜3 | W*g*A〜D | 届いた課題の数の順、K = 8 | B・A・B |
| `open` | 1〜3 | O*g*A〜D | 容量なし（使用回数順） | B・A・B |
| `fixed` | 1〜3 | F*g*A〜D | 使用回数順、K = 8 | A・A・A |

被験体は学習と held-out の区別を知らず、課題は族の名前順に並ぶ。held-out の結果は採点・報告するが、
どの規則でも次の辞書の選定に入らない。

### B.3 手順と停止条件

```sh
node cli.mjs evolve <run> base 0 8 --into uses
node cli.mjs evolve <run> base 0 8 --rule breadth --into breadth
node cli.mjs evolve <run> base 0 Infinity --into open
node cli.mjs evolve <run> base 0 8 --into fixed
# 世代 g = 1, 2 の後（条件ごと）
node cli.mjs evolve <run> uses <g> 8
node cli.mjs evolve <run> breadth <g> 8 --rule breadth
node cli.mjs evolve <run> open <g> Infinity
node cli.mjs evolve <run> fixed <g> 8
node cli.mjs seal <run> <cond> <g>
# 最後に
node cli.mjs unseal <run> && node cli.mjs analyze <run>
```

停止条件は世代 0 の正答が 30% 未満（176 問中 53 問未満）のみ。天井では止めない。世代 1 以降に
ある条件の 4 体のうち 2 体以上が解答を書けなければ、その条件を止める。今回はどれにも当たらな
かった（世代 0 は 175/176、解答を書けなかった体はない）。
