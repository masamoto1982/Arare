## 6. 誤答

| 体 | 課題 | 原因 |
| --- | --- | --- |
| L1C（Haiku） | `series.mad`（held-out） | 入力を束縛した後に `X X` と 2 回積み、1 つがスタックに残った |
| L2D（Fable） | `number.collatz` | `FOLD` の初期値と Vector の順を逆にし、自前の語の `BIND` が 130 要素を 2 名に分けられなかった |
| L3D（Fable） | `sensor.scaled` | `SELECT` の候補を逆に置いた（下記） |
| P1D（Fable） | `sensor.scaled` | 同上 |
| P3D（Fable） | `sensor.scaled`・`sensor.ratios` | 同上 |

Fable の 3 体（定義の可否が違う条件にまたがる）が、同じ形の式 `NIL X 1 X NIL? SELECT …` を書いた。
意図は「X がなければ 1、あれば X」だが、`SELECT` は `whenTrue whenFalse truth` の順なので
「X がなければ X（NIL）、あれば 1」になり、存在する読みがすべて 1 に置き換わった。SKILL.md の
既定値の例 `-1 SQRT 'S' BIND 99 S S NIL? SELECT` には「S, or the fallback if S is absent」と
注記がある。注記は S、既定値の順に読むが、コードは既定値、S の順に並ぶ。3 体の誤った式は、どれも注記の
語順と同じ並び（X、既定値）だった。注記が原因かどうかは、この 3 件だけでは分からない。

## 10. 次に進むなら（観察から。決定ではない）

1. SKILL.md の既定値の例の注記を、コードの順に合わせる（例: 「the fallback when S is absent, else S」）。
   今回の 6 件の誤答のうち 4 件がこれで、Phase 3・4 の `SELECT` の誤りとは別の種類である。エラー文の
   ヒントでは防げない（誤った式もエラーにならずに値を返す）。
2. 辞書の効果を測る量は、労力（使用量）ではなく書く量である。使用量は文書を読む分が支配し、どの
   条件でも動かない。今後の比較は「1 体が書いたトークン数」を主にするのが筋である。道具はまだこれを
   出さない（今回は手で集計した）。
3. 組をまたぐ一般性を測るには、選定が世代をまたいで数える必要がある。例えば「直近 2 世代（両方の
   学習組）で届いた族の数」で並べれば、片方の組の系統にしか効かない語は上に来ない。
4. 1 類 1 枠では、働きが同じでも書き方が違う語（2 つの最大値）が両方入る。プローブの答えが違う
   入力（文字列・入れ子）で差が出る語を、数の Vector でだけ比べる別の同一性を足すかどうかは、
   所有者が決める。
5. どれに進むかは所有者が決める。

```json
}
```

| 条件 | 世代 | 被験体 | 辞書 | 自前の定義 | 学習課題 |
| --- | --- | --- | --- | --- | --- |
| `base` | 0 | G0A〜G0D | なし（Phase 4 の提出を再利用） | 可 | A |
| `families` | 1〜3 | L*g*A〜D | 前の世代から、族の数の順、K = 8 | 可 | B・A・B |
| `probe` | 1〜3 | P*g*A〜D | `families` の同じ世代と同じ | 不可 | B・A・B |
| `bare` | 1・2 | N*g*A〜D | なし | 不可 | B・A |

定義を禁じた被験体へのプロンプトは「自前の Word を定義してはならない。Core と継承語だけで書き、
`definitions` は空にする。提出した定義は採点で無視される」と伝え、提出の雛形の `definitions` を
`[]` にした。解答の中の `DEF` や、`BIND` したブロックの `EXEC` は止めなかった（その解答の中でしか使えず、
トークン数もその解答に数えられる）。

### B.3 手順と停止条件

```sh
node cli.mjs evolve <run> base 0 8 --rule families --into families
node cli.mjs evolve <run> base 0 8 --rule families --into probe
# 世代 g = 1, 2 の後
node cli.mjs evolve <run> families <g> 8 --rule families
node cli.mjs evolve <run> families <g> 8 --rule families --into probe
node cli.mjs seal <run> <cond> <g>
# 最後に
node cli.mjs unseal <run> && node cli.mjs analyze <run>
```

条件どうしは独立なので、辞書の揃った条件から次の世代へ進めた（`probe`・`bare` の世代 2 は
`bare` の世代 1 の最後の 1 体を待たずに始めた）。停止条件（世代 1 の `bare`・`probe` で 4 体中 2 体
以上が解答を書けない・課題を放棄する、または定義の禁止を破る）には当たらなかった。
