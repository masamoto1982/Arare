# Rust 実装を 1 万行程度に縮める計画（2026-10-12）

Status: non-canonical. 作者の方針「Rust のコード量を 1 万行程度に抑える」を受けた
計画。削減は以下の段階ごとに行う。

## 決定事項と進捗（2026-10-12 更新）

作者の判断（2026-10-12）:

- **数え方。** 「1 万行」は本体の実コードだけを数える。`rust/src` のうち、テスト
  （ファイル名に `test` を含むもの、`*_laws.rs`、インラインの `#[cfg(test)] mod`）、
  生成物（`kernel/generated/`）、空行、コメント行を除いた行数。
- **速度。** 遅くなる変更は採らない。削減はむしろ速くするために行う。各段で
  `rust/examples/speed_bench.rs` を main と交互に走らせ、ケースごとの最良値で比べる。
- **`SQRT` の無理数（`types/exact`）は残す。**
- **契約推論は `field` と入出力数だけ残す。** `shapes`・コスト・空間・NIL 方針・純粋性・
  決定性の推論と、それらの宣言の照合を外した。`CONTRACT` の答えは `inputs` `outputs`
  `field` の Record。`spec/words.json` の `zeroShapes` も外した。
- **診断はエラーと NIL の理由だけ残す。** `diagnosis`・`aiDiagnostic`・`errorFlowTrace`・
  次の確認の提案・綴りの候補・`outcomes` の予測を外した。エラーは `message` と
  `error { category, resource, word, line, column }`、NIL は `reason` と `detail` だけを持つ
  （エンベロープの schemaVersion 4）。
- 後方互換性と既存利用者への配慮は不要。

実行エンジンの一本化: プログラム・語の本体・ブロックはすべて `engine::Code`（`Op` の列）に
コンパイルして一つのループで走らせる。トークン列を直接たどる経路、`compiled_plan`、
`segment`、`symbol_cache` を外した。Core Word はコンパイル時に解決し（Core は封印済み）、
それ以外の名前は実行時に解決するので、`Code` は辞書に依存せず古くならない。語の本体の
`Code` は定義に一度だけ持つ。`'X' BIND` で束縛する名前はフレームのスロットに置き、読みは
O(1)。User Word の名前解決は辞書エポック付きの小さなキャッシュで引く。束縛名と User Word
名は互いに排他（`BIND` も `DEF` も相手の名前を拒む）なので、引く順序は自由。

列ウォーク（`MAP` `FILTER` `FOLD` `SCAN`）の前段の一本化: ブロックの `Code` を一度だけ
レジスタ形式（SSA）に下ろし（`fused_block_lower`）、種類（数か真理値）の型付けも一つに
した（`FusedBlock::types`）。実行は同じ命令列を三つの表現で走らせる。機械語の整数を
列単位で（`fused_block_int`）、機械語に収まる有理数の組で（`fused_block_rat`）、任意の
平易な値で（`fused_block_general`）。汎用段は組の速い道と列への直接の集約を持つ。
有理数段を汎用段に吸収すると要素あたり 2.3 倍遅くなるので（250 対 590 命令）、三段は残す。

列カーネルの共有: 要素ごとの Word（`ADD` `DIV` `FLOOR` `GT` など）の列カーネル
（`dense_kernels`）を列ウォークと共有した。カーネルは結果を `Out`（分子と分母の列。
すべて整数の間は分母を書かない）に書き、Word はそれを Tensor に包み、ウォークは
レジスタごとに一つ持って 256 要素ずつ命令を走らせる（`fused_block_columns`）。
これで整数段（`fused_block_int` `fused_block_reg`）と有理数段（`fused_block_rat`）、
`simd_ops` を外した。有理数の MAP は gcd を 4 本並べるカーネルを使うようになり速く、
`FOLD`/`SCAN` は累積器を読まない命令だけ列で、残りは要素ごとに組で走らせる。
順序のない点（`1/0` `0/0`）を含む比較は、カーネルがそのレーンを `domainMiss` の NIL に
してその場で答える（以前は一般経路でレーンごとに箱に入れていた）。

ホットスポット: `RANGE` は列を添字から直接書き（ベクトル化される）、要素ごとの push と
飽和加算をやめた（命令数 0.34）。NIL の欠落情報は理由だけなら値の中に持ち
（`NilAbsence`）、`ABSENT` の文字列があるときだけ箱に入れる。理由だけの NIL は共有の
静的な表を指すので、要素ごとに NIL を作る Word が割り当てをしない。字句解析と、
DIV の gcd（4 本並べた二進 gcd）は、命令が薄く広がっていて、これ以上は構造を変える
必要がある（字句をエンジンへ直接流すなど）ので、ここでは手を付けない。

数の表現の一本化（段 5 の読み替え）: BigInt 一本にすると機械語の有理数が一桁遅くなるので
採らず、二重表現（`Small`/`Big`）は残して、その上の重複を外した。`Fraction` は常に
正準（既約、分母は正か二つの点、両半分が機械語に収まるときに限り `Small`）なので、
等値とハッシュは組をそのまま比べる（以前は交差乗算と、ハッシュのたびの gcd）。
機械語の組の加減乗除と比較はスカラーの `Fraction` も `small_rational` を通り、列カーネルと
同じ一つの実装になった。`Big` の乗算と除算は一つ（除算は除数の組を入れ替えた乗算）。
テンソル乗算の疎表現（`SparseTensor`）は列カーネルが断ったときだけ走る二つ目の表現
だったので外した。`harmonic-2000` を支える大きな数の高速化（Lehmer の gcd、1 語の除数、
1 語の項との和）は、外すと 45 倍遅くなるので残す。
`BSEARCH` は昇順の確認をテンソルに一度だけ記録する（`DenseTensor::ascending`）。キーに
持ち上げた検索や、束縛した表への繰り返しの検索は、全レーンを読み直さない。
計測では、命令数が同じまま列カーネルの速さがリンカの配置で 2 割変わっていた（関数の
先頭が 64 バイト境界から 16 バイトずれた）。x86_64 のビルドは関数を 64 バイトに揃える
（`rust/.cargo/config.toml`）。

エージェント境界の整理（段 6）: ホストプロトコル（`spec/host-protocol.schema.json`）が
求めないものを外した。実行の受領書（`receipt`）と観測ダイジェスト（`observationDigest`）
は、検証するホストがどこにもなく、MCP は受領書を三つの項目に削ってから送っていた。
エンベロープは schemaVersion 5。値のダイジェスト（`DIGEST` 語と User Word の同一性が
使う）は `interpreter::value_digest` に移した。`check` は常に `#:contract` を検証し
（`--contract` を外した）、`agent` は `--json` を受け付けない。`compute` は実行前に
字句解析を二度しない。`contract_violation` は `contract` に入れた。`stackElided`、
`outcome`、`contractDecls`、`resourceUsage` はスクリプトや仕様が読むので残す。スタック全体の
ダイジェストを取らなくなったので、大きな結果を返す `agent compute` は 2.2 倍速い。
`agent/` は 4,100 行の見込みに対し、段 6 の前にすでに 1,640 行まで減っていたので、
減少は見込みの 3,000 行に届かない。

細かな整理（段 8）: 段 1〜6 の改修を Fable で見直し、挙動・仕様・速度を変えない整理だけを
した。使われない関数・フィールド・定数（`Value::get_child` `first` `last`
`as_dense_tensor` `is_tensor`、`Stack::reverse` `fresh_start`、`EpochSnapshot`、
`global_epoch`、`runtime_scratch`、`MAX_MATERIALIZED_ELEMENTS` ほか）、エンジンが同じ
条件で断った直後にもう一度試していたスカラー経路の再試行、無理数ベクトルの平坦な場合
だけの別経路（一般の経路が同じ値を作る）、正準な分数では何もしない再約分（値の
ダイジェスト）を外し、`is_absent` `is_operational_nil` を `is_nil` にまとめた。CLI
専用の `Opts` は `cli` へ移し、WASM ビルドの警告を消した。消えたモジュールや経路を
指すコメントを直し、テストの重複した観測ヘルパーを `route_observation` にまとめた。

残り約 12,900 行。内訳は解釈器 11,000、数（`types`）6,900、実行経路の高速化 3,700、
`agent` 1,700、CLI 900。速度を落とせないので、方針 1（経路を外す）はそのままでは採れない。
経路は「一本の速い経路に統合する」方向で減らす（下の段 1〜3 を読み替える）。

## 目標

- 本体 1 万行程度。テストは別枠とし、適合コーパス（`tests/conformance/index.html`）を
  主な検証手段にして、Rust のテストは 5 千行程度に抑える。
- 外から観測できる振る舞い（適合コーパス、ホストプロトコル、コスト契約）は変えない。
  変えるときは仕様の版を上げ、その PR で名指しする。

## 方針

1. **実行経路を一本にする。** 高速化経路をすべて外し、参照評価器だけを残す。
   レビューが指摘した「点の意味が経路ごとにずれる危険」と「経路ごとの 100 倍の性能の崖」
   は、経路が一本になれば両方とも消える。`route_differential_tests.rs` は削除の各段で
   残す経路と参照評価器の一致を確かめる安全網として使い、最後の経路と一緒に消す。
   コスト契約（steps・numeric・collection）は語ごとに定義されており経路に依存しない
   ので、計量は残す。
2. **数の表現を一つにする。** `Fraction` の Small/Big 二重表現と Henrici 加算などの
   高速経路をやめ、BigInt の既約対一本にする。
3. **生成物を小さくする。** 語レジストリは `spec/words.json` をビルド時に読む形にし、
   Rust ソースとして 3,900 行を生成しない。
4. **境界と診断を絞る。** ホストプロトコルが要求するものだけを残し、`agent/` と診断を
   一つの報告モジュールにまとめる。
5. **三値化と一緒に論理を縮める。**（2026-10-12 に実施。`three-valued-truth.md`）三値論理の PR で `BOTH` と `RECONCILE` の BOTH 規則が
   消えれば、真理値表と関連の分岐が減る。

## 作者の判断が必要なこと

以下は 2026-10-12 に決着した（上の「決定事項」）。記録のために残す。

- **`SQRT` が作る無理数（多重二次体）を残すか。** `types/exact` と平方因子分解で
  約 2,400 行、表示・比較・FORMAT への波及を入れるとさらに多い。残すなら 1 万行は
  かなり厳しい。完全平方だけを有理数で答え、それ以外を `domainMiss` にすれば大きく減る。
- **契約推論の範囲。** `field`・`shapes`・コスト・NIL 方針・決定性を全部推論するか、
  `field` と入出力数に絞るか。README が新規性の中心に置くのは `field` の推論。
- **エージェント境界の機能。** `outcomes` の予測、`infer_contracts`、観測ダイジェスト、
  受領書のうち、MCP サーバーが本当に必要とするもの。
- **速度の約束。** 経路を一本にすると整数 MAP/FOLD は現在の数 ns/要素（WASM）から一桁以上
  遅くなる見込み。許容する上限を決めておく。
