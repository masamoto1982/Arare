# 分数の輪への移行（2026-10-12）

Status: non-canonical. 正典は `spec/language-semantics.md` の LANG.VALUES.EXACT と
LANG.VALUES.SHAPE。本書は判断の理由だけを記録する。

## 何を変えたか

数を「0 でない整数倍の違いを同一視した整数の組」とした。正規形（既約・分母非負）は
変わらないが、因数 `-1` が `(1, 0)` と `(-1, 0)` を結ぶので、0 の上の組は `1/0` と
`0/0` の二つだけになる。`-5 0 DIV` は `1/0`、リテラル `-1/0` は `1/0` の別の綴り。
和・積・逆数の公式はそのまま。帰結は二つ。

1. 逆数が対合になり、`/(xy) = /x /y` も全域で成り立つ。Carlström の輪の公理はすべて
   成り立つ（`rust/src/zero_shape_laws.rs` が実行して確かめる）。
2. `1/0` は符号を持たないので順序を持たない。`LT` `GT` `MIN` `MAX` `SORT` `ORDER`
   `BSEARCH` は `0/0` と同じく `domainMiss` を投影する。

## なぜ

外部レビュー（2026-10）が、移行前の体系は輪でも超実数（transreal）でもない中間だと
指摘した。符号付きの点を残したことで逆数が対合でなくなり（`//(-1/0) = 1/0`、
`/(0·-2) ≠ /0·/-2`）、一方で `1/0 + 1/0 = 0/0` なので正の数どうしの和が順序の外へ
出る。符号を残す理由だった順序との整合も、輪の公理も、どちらも取れていなかった。
README の「超実数算術を体に制限したもの」という記述も事実と違っていた。

選択肢は (a) 符号なしの ∞ にして本物の分数の輪にする、(b) Anderson に倣って
`∞ + ∞ = ∞` とし順序を取る、の二つ。(b) も一度実装して全テストが通ることを確かめた
（コミットはしていない）うえで、作者の方針により (a) を採った。理由:

- 公理が欠けない。逆数・和・積の公式が例外なしに成り立つので、点の意味を経路ごとに
  再実装する余地が減る（Rust を 1 万行程度に抑える方針と整合する。
  `rust-10k-reduction-plan.md`）。
- 順序を失う代価は小さい。順序を問われた点は `domainMiss` という理由つきの不在になり、
  `0/0` ですでに用意されていた経路に乗るだけで、新しい概念を足さない。
- 三値論理（SQL 型 Kleene）への移行構想と相性がよい。比較が決まらないときは
  UNKNOWN、`FILTER` は SQL の `WHERE` と同じく UNKNOWN を落とす。

## 捨てたもの

- 符号付き無限大と、それを前提にした「三すくみ」の議論、素数座標の法則テスト
  （`zero-shape-arithmetic.md` の該当節は記録として残す）。
- `1/0` の上下の順序（`-1/0` が最小、`1/0` が最大）。
- `-1/0 SQRT` が負の被開平数として `domainMiss` になる規則（`1/0 SQRT` は `1/0`）。

## 変えなかったもの

- `FILTER` は述語が UNKNOWN の要素を落とす。レビューは「黙って捨てる」と指摘したが、
  三値化の方針では SQL の `WHERE` と同じ振る舞いが正しいので、README の約束の方を
  書き直した。
- `SORT` などは順序のない要素が一つでもあれば全体が `domainMiss`。要素ごとの演算とは
  違い、答えが全要素の順序に依存するので、README にそう書いた。
- `BOTH` を渡された `SELECT` は二つの候補を `RECONCILE` した値を答える（等しければ
  その値、違えば `conflict`）。三値化の PR で BOTH ごと廃止した（`three-valued-truth.md`）。
