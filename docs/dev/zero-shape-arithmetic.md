# 零形算術（zero-shape arithmetic）

Status: non-canonical. 方針記録。正典は `spec/language-semantics.md` の
LANG.VALUES.SHAPE・LANG.VALUES.EXACT・LANG.VALUES.TRUTH のみ。本書は採用した
判断とその理由、次の一手を記録し、何も定義しない。

## 判断

Ajisai の数を「ゼロ除算を許す有理数」ではなく、**分数を組として扱い切った算術**
として位置づける。組 a/b を (a≠0, b≠0) の二ビットに写すと、四つの零形
F=`0`・T=`±1/0`・N=`0/0`・B=その他 が得られ、これは Belnap の FOUR そのもので
ある。この読みを LANG.VALUES.TRUTH の末尾段落から独立した節 LANG.VALUES.SHAPE に
昇格し、次の事実を正典に置いた。

- 積の零形は知識順序の下限 ⊗、逆数は NOT、和は (ad∨bc, bd)（B+B の打ち消し
  だけが例外）。
- 各零形は `MUL` について群（K*、Z/2、自明、自明）で、数全体は FOUR の上の
  Clifford モノイドである。ゼロ除算は領域の外へ出ることではなく層を移ること。
- 車輪（Carlström）の公理のうち加法にかかわる W4・W5・W7・W8 は三点を含めて
  すべての点で成り立つ。
- 破れるのは逆数の対称性だけで、場所も特定できる。`//x = x` は `-1/0` でだけ、
  `/(xy) = /x·/y` は「0 と負の有限数」の組でだけ、分配法則は乗数が `±1/0` の
  ときだけ破れる。
- RECONCILE（⊕）の算術側の影は中間数 (a+c)/(b+d) で、語を足さずに書ける。
  `0` と `1/0` から Stern–Brocot 木として正の有理数をすべて生む。ただし値の
  上では結合的でない（合わせた順序を値が覚える）。

いずれも `rust/src/zero_shape_laws.rs` が実行によって検査する。

## 三すくみと、符号付きゼロを入れない理由

次の三つは同時には取れない。

1. 無限に符号がある（`-1/0 < x < 1/0` という順序）
2. 逆数が対合で、積と可換（W2・W3）
3. 加法の車輪公理（W4・W5・W7・W8）

IEEE 754 流に ±0 を足すと 1 と 2 が取れ、3 が 14〜48 件破れる（仮想モデルでの
検算）。無限を一つにすると 2 と 3 が取れ、順序を失う。Ajisai は **1 と 3 を取る**。
失うのは `-1/0` の周りの逆数だけで、順序（`0/0` 以外で全順序）と加法の法則は
残る。損失がもっとも小さいので、仕様で「符号付きゼロを足して、または二点を
同一視して第三の性質を取り戻してはならない」と固定した。これは LANG.VALUES.EXACT
の「特別扱いで法則を取り戻してはならない」と同じ規律の延長である。

## 中間数を Word にしない理由

`RATIO`・`ADD`・`GET`・`DIV` で書けるので、語彙採用規則（「言語内で書けない語」
か「導出可能な語との入れ替え」）のどちらにも当たらない。正典には算術の構造上の
事実として書き、語は増やさない（当時 78 語のまま。のちに `BOTH` の退役で 77 語）。

## field 契約を零形で推論する（採用）

`field: closed / leaving` は零形を二値（{F, B} にとどまるか、{T, N} に出うるか）に
潰したものだった。これを零形のまま推論するよう改めた（LANG.CONTRACT.FIELD）。

- 各 Core Word の零形の法則は、2026-10 の契約推論の縮小で `spec/words.json` の `zeroShapes` とともに廃止した（`field` はその射影だけが残る）
  （`none` `carry` `count` `carryCount` `finite` `parse`、和・差・積・商・冪・根・丸めの
  表、ブロックを走らせる `map` `filter` `fold` と追わない `exec`）。`field` はその射影で、
  `zero_shape_contract_laws.rs` が一致と健全性（全 Word を全零形の被演算子で実行し、答えが法則の
  予測に入ること）を検査する。
- 推論はスタックを模擬し、各値がとりうる零形を符号つき（0・正・負・+∞・−∞・0/0 の
  六原子）で運ぶ。符号を持つのは、冪の指数（負なら 0 が `1/0` になる）と和（同符号は
  打ち消さない）が符号で決まるから。契約が報告するのは四つの零形 `zero` `nonzero`
  `infinite` `nullity` で、新しいキー `shapes` に入る。`field` は `shapes` が
  {zero, nonzero} に収まるかの射影になった。
- 効果：除数がリテラルでなくても形で決まれば `closed`（`[ 2 SQRT DIV ]`、
  `[ LENGTH 1 ADD DIV ]`）。`[ 0 MUL 0 DIV ]` は `zero` と `nullity` だけで符号つきの
  点に届かない、と言える。`nullity` を含まない本体は、`0/0` に順序を問わない
  （算術から UNKNOWN に入る唯一の経路を静的に閉じる）。
- 模擬が成り立たない所（可変アリティの Word、`EXEC`、リテラルでないブロック）では
  従来の呼び出しごとの結合に戻り、`shapes` はその値が許す最も広い集合になる。この
  集合は `#:contract … shapes=…` を反証しない（注記にとどまる）。

## ファミリーを二つの順序で分ける（採用）

数と真理値に関わる語の族を、旧 `booleanLogic`・`comparison`・`exactArithmetic` の三つ
から、FOUR の二つの順序に沿った二つへ組み替えた（LANG.VALUES.SHAPE）。

- `knowledgeOrder`（知識順序）: 算術の語（`ADD` `SUB` `MUL` `DIV` `FLOOR` `ROUND`
  `SQRT` `POW` `GCD` `RATIO`）と `RECONCILE`。値について何が分かっているかに働く語で、
  全員が LANG.VALUES.SHAPE を共有法則として引用する。積は ⊗、`RECONCILE` は ⊕。
- `truthOrder`（真理順序）: 真偽値と結合子（`TRUE` `FALSE` `AND` `NOT` `SELECT`。
  当初は `BOTH` も含んだが、三値への移行で退役した）と、順序を問う語（`EQ` `LT` `GT` `MIN` `MAX`）。全員が LANG.VALUES.TRUTH
  を引用する。`MIN` `MAX` は数の順序の下限・上限で、`0/0` に順序を問えば UNKNOWN に
  なるという同じ橋を渡るので、算術ではなくこちらに置いた。
- 二つが出会うのは逆数と `NOT`、そして UNKNOWN として読まれる `0/0` である。

族の数は 11 から 10 に減った（上限 12）。族は語の共有法則を選ぶものなので、分け方を
「どの順序に働くか」にそろえると、族の共有法則がそのまま零形算術の二つの面になる。

## SUB を退役候補の列の先頭へ（採用）

`SUB` は零形の読みでは固有の法則を持たない唯一の導出可能語である（その零形の表は
符号を反転した被演算子に和の表を当てたもので、`x y -1 MUL ADD` と同じ）。
車輪の演算にも減算はなく、和と逆数だけがある。一方で最も使われる導出可能語でもあるので、
今すぐ退役させる（既存のプログラムが壊れ、高速化経路の削除も伴う）のではなく、
退役候補の列（`scripts/check-minimal-core.mjs`）の先頭へ移した。次に語を一つ採用する
ときには、`SUB` がまずその枠を譲る。語数は 78 のまま。

## 真理順序の ∧ に当たる算術（採用）

組の二つの半分で読むと、積は AND、和は OR に落ちる（分母は負にならないので和が
打ち消されない）。分子と分母をそれぞれ積でまとめるか和でまとめるかの四通りが、
FOUR の四演算になる（LANG.VALUES.SHAPE）。

| 分子＼分母 | 積 | 和 |
| --- | --- | --- |
| 積 | `ac/bd` ＝ `MUL`（⊗） | `ac/(b+d)` ＝ ∧ |
| 和 | ∨（ド・モルガンで `1/((1/x) ∧ (1/y))`） | `(a+c)/(b+d)` ＝ 中間数（⊕） |

- `ac/(b+d)` は、負の数を含む有理数の全組で零形が真理順序の ∧ に厳密に一致する
  （`1/0` が単位元、`0` が吸収元）。中間数と同じく値の上では結合的でない。
- 体の演算として書けるのは ⊗ だけで、それ以外はありえない。`0/0` は体の演算すべてに
  吸収されるので、加減乗除の句は UNKNOWN を UNKNOWN に送る。FOUR の四演算のうち
  UNKNOWN が吸収されるのは ⊗ だけ（∧ は UNKNOWN と FALSE を FALSE に、∨ は UNKNOWN と
  TRUE を TRUE に、⊕ は UNKNOWN を相手に譲る）。残る三つは組を読む（`RATIO`）しかない。
- 体が書けるのはその影で、∨ には `ADD`、∧ にはその逆数双対の並列和
  `1/(1/x + 1/y)`。どちらも零形で一致するが、`0/0` が吸収する所、打ち消す所、
  二つの点が出会う所（`1/0 1/0 ADD` と `0 0` の並列和がともに `0/0`）でだけ外れる。
- 抵抗の合成が同じ対になる。直列は和で開放（`1/0`）が支配し、並列は並列和で短絡
  （`0`）が支配する。

語は増やさない（`RATIO` `GET` `MUL` `ADD` `DIV` `BIND` で書ける）。
`rust/src/zero_shape_lattice_laws.rs` が、組の ∧ と双対の ∨ の厳密一致、体の演算に
よる `0/0` の吸収、影が外れる場所の完全な予測を、実行して検査する。

## 素数の座標（採用）

素因数分解の一意性を三点へ延長すると、掛け算の側がすべて座標で書ける
（LANG.VALUES.SHAPE）。数は符号と素数ごとの指数の組で、`0` は指数がすべて +∞ で符号を
持たず、`±1/0` は指数がすべて −∞ で符号を持ち、`0/0` は指数を持たない。

- `MUL` は符号を掛けて指数を足す（+∞ と −∞ の和は「なし」＝ `0/0`）。逆数は指数の
  符号を反転する。零形はこの座標の層そのもの。
- 逆数の唯一の非対称は「ゼロが符号を忘れ、点は符号を保つ」ことで、`-1/0` の逆数の
  逆数が `1/0` になる理由はこれに尽きる。
- 和は「小さい指数が勝ち、等しい指数どうしは打ち消しうる」。`1/0 1/0 ADD` が `0/0`
  なのは `1 -1 ADD` が `0` なのと同じ現象で、点にはそれを決める細かい桁がない。
- 解釈（定理ではない）: 符号付きの点と順序は実数としての順序（符号）の側から、車輪の
  公式は各素数の指数の側から来る。超実数と同じ点に車輪の公式が乗る理由がここにある。

表現には使わない。素因数分解したまま計算すると足し算のたびに分解し直すことになり、
連分数（性能上の理由で過去に棄却済み）より重い。素数を実際に計算するのは今も
`SQRT` が平方因子を取り出すときだけである。`rust/src/zero_shape_prime_laws.rs` が
掛け算・逆数と座標の一致、和の指数の規則を実行して検査する。

## 複素数（不採用）

i ＝ √−1 を足すと `SQRT` は全域になり、等しさも決定可能なままだが、採らない。

- 順序を失う。値の領域の条件（等しさと順序を有限時間で決める）に反し、順序を問う語に
  `0/0` 以外の UNKNOWN の入口ができる。
- 符号付き無限を失う。既約な組をガウス整数に広げると、無限の層の群は単数群になり、
  `1/0` `i/0` `-1/0` `-i/0` の四つの無限ができる（整数の単数 ±1 が今の二つの無限）。
  逆数は四つの無限を一つのゼロへ送る。四つを一つにまとめれば Carlström の符号なし
  車輪で、三すくみの別の頂点へ移ることになる。
- 正規形の項数が倍になる。

## 三すくみの修正と文献調査

当初の「符号付き無限・逆数の対合・加法の車輪公理のうち取れるのは二つまで」は、条件
なしでは偽だった。Carlström の分数の車輪を正の分母だけで作る（正のスカラーでのみ
同一視する）と、三つすべてを満たす。その代わりゼロに符号が付き、すべての数に鏡像が
できる（`-1/-2` と `1/2` が別）。仕様は次の形に正した。

1. ゼロが一つなら、符号付き無限と逆数の対合はそもそも両立しない（逆数が二つの点を
   一つのゼロへ送る。鳩の巣原理）。
2. 符号付きゼロだけを足せば対合は戻るが、加法の車輪公理が崩れる。
3. 三つすべてを保つには鏡像が要り、それは「体とゼロの上の三点」ではなくなる。

文献（Bergstra のサーベイ 2019、有理数の車輪と超有理数の抽象データ型としての扱い
（Bergstra–Tucker）、common meadow（Bergstra–Ponse）、Carlström 2004）を調べた範囲
では、「超有理数と同じ点」と「車輪の公式（∞+∞ ＝ ⊥）」を組み合わせた体系の既存の名前は
見つからなかった。近い親は有理数の車輪（公式が同じで無限が符号なし）と超有理数（点が
同じで ∞+∞ ＝ ∞）。ネットワーク方針で論文本文は読めず、要旨と引用に基づく。
